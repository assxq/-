# 낡은 미래 — 영상 제작 워크플로우 (현재 기준, E01부터)

> 이 문서는 **지금 저장소에 있는 것**과 **앞으로 해야 할 일**을 순서대로 잇는다.
> 참고한 사례: THE PATCHWRIGHT의 공개된 제작 방식 (Midjourney로 기준 컷 → Nano Banana로 수정 → Kling으로 **샷 하나씩** 애니메이션, 멀티샷 자동 기능은 쓰지 않음). 이 정보는 2차 기사에서 확인한 것이고 원문 스레드는 직접 열람하지 못했다.
> 쓸 영상 도구는 **아직 확정되지 않았다.** 1단계 비교 테스트로 정한다.

## 0. 한눈에
```
[1 도구 비교] → G1 → [2 입력 이미지] → G2 → [3 클립 생성·검수] → G3 → [4 조립] → G4 → [5 사운드] → G5 → [6 QA·업로드]
   1시간          도구 확정   A-H, B1, B2, C     이미지 합격    C3→C1→C4→C2(+S6)   클립 합격   assemble      타이밍 일치   실제 폴리 + 마스터   -16 LUFS    체크리스트
```
- 각 단계 끝의 **G(게이트)**를 통과해야 다음으로 간다. 통과하지 못하면 **플랜 B**로 내려간다. 플랜 B로 내려가도 영상은 반드시 완성된다.
- **영상을 끝까지 완성하는 것이 우선이다.** 클립 하나가 계속 실패하면 그 샷만 정지 이미지로 대체하고 나머지는 계속 진행한다.

### Claude와 작업하는 방법 (파일 전달)
Claude는 클라우드 세션의 저장소에서 작업하므로 **파일이 저장소에 있어야** 분석·조립할 수 있다.
1. 생성한 클립을 **본인 PC에서** `production/E01/generated/` 아래 해당 폴더에 넣는다.
2. 브랜치 `claude/dreamy-pasteur-7bs4ip`에 **푸시**한다. (GitHub 웹에서 파일 업로드도 가능. 웹 업로드는 파일당 25MB 이하)
3. "후보 올렸어요"라고 알려 주면 Claude가 검수와 조립을 진행한다.
※ **직접 하는 방법**: 본인 PC에 Python 3, Pillow, numpy, ffmpeg가 있으면 `python3 production/tools/assemble.py --ep E01` 를 직접 실행해도 된다. (아래 4단계)

## 4. 단계별 작업

### 1단계 · 도구 비교 테스트 (예상 1~2시간)
**목적**: 이 스타일(80년대 에어브러시 애니 일러스트)에서 어느 도구가 가장 안 무너지는지 정한다. 비교 글은 대부분 실사 위주라서 **직접 확인해야 한다.**
**입력**: `source/mia_base_A.png`, 초단위 설계서의 **C1 프롬프트 A**
**할 일**
1. 후보 도구 3개를 정한다. 기본 추천: **Kling 3.0 · Veo 3.1(Fast) · Runway Gen-4.5**. (Seedance 2.0은 선택)
2. 도구마다 **같은 설정**으로 4번씩 생성한다: 9:16 · 5초 · 모션 낮음 · 카메라 고정 · 같은 프롬프트 · 같은 시작 프레임
3. 파일을 `generated/bakeoff/<도구>_<번호>.mp4`로 저장한다.
4. 각 파일을 검수한다: `python3 production/tools/review_clip.py <파일> --offset 1.5`
5. LOG.csv에 기록하고 아래 표를 채운다.

| 도구 | 입 움직임(낮을수록 좋음) | 얼굴 drift | 시선이 왼쪽 위로 이동? | 렌즈 응시 | **화풍 유지 1~5** | 클립당 비용 | 대기 시간 |
|---|---|---|---|---|---|---|---|
| (채움) | | | | | | | |
**화풍 유지**는 눈으로 판단한다: 일러스트의 에어브러시 질감이 유지되는가, 3D·실사풍으로 변하는가.

**G1 (통과 기준)**: 4번 중 **2번 이상**이 ① 입이 닫혀 있고 ② 같은 사람이며 ③ 시선이 왼쪽 위로 움직이고 ④ 화풍 4점 이상이면 그 도구를 **C1·C4용**으로 확정한다.
**막히면**: 어느 도구도 통과하지 못하면 → ① 프롬프트 B, C(키프레임)로 한 번 더 → 그래도 안 되면 **C1·C4는 플랜 B(정지 이미지 + 디졸브)**로 가고 나머지 클립만 진행한다.

### 2단계 · 입력 이미지 세트 (예상 2~3시간)
**목적**: 클립의 시작·끝 프레임이 될 이미지를 같은 스타일로 만든다.
| 순서 | 이미지 | 만드는 법 | 쓰임 |
|---|---|---|---|
| 1 | **A-H** 헤드셋 클로즈업 | 이미지 **수정** 도구(Nano Banana류)로 A를 재구성 | C2 시작 |
| 2 | **A-L** 램프를 보는 시선 | 이미지 수정으로 A의 시선만 변경 | C1 중간 키프레임(선택) |
| 3 | **A-W** 창을 보는 시선 | 이미지 수정 | C4 끝 프레임(선택) |
| 4 | **B1** 카세트가 입구에 걸친 데크 | 새로 생성 (A를 **스타일 참조**로) | C3 시작 |
| 5 | **B2** 같은 구도, 카세트 안착 + 도어 닫힘 | **B1을 수정**해서 생성 (구도 고정) | C3 끝 |
| 6 | **C** 데크 위의 손 | 새로 생성 | S6 (정지 이미지) |
프롬프트는 설계서 4절. 결과는 `generated/images/`에 저장한다.
**G2 (통과 기준)**: 설계서 4절의 이미지별 검수 항목을 모두 통과 / **B1과 B2의 데크가 같은 물건** / 손은 **정확히 5개의 손가락**.
**막히면**: C(손)가 안 나오면 손 없는 데크 컷으로 대체. A-L, A-W는 선택이라 건너뛰어도 된다.

### 3단계 · 클립 생성과 검수 (예상 3~6시간)
**순서: C3 → C1 → C4 → C2 → (S6)**. C3(데크)는 사람이 없어서 실패가 적고 소리와 가장 촘촘히 맞물려서 **가장 먼저** 해서 자신감을 얻는다.
**클립마다 반복**
1. 시작·끝 프레임을 지정하고(지원 시) **프롬프트 A**로 후보를 뽑는다. (C1·C4 8개, C2·C3 6개)
2. 후보를 `generated/candidates/<클립>/`에 이름 규칙대로 저장하고 LOG.csv에 기록한다.
3. **C1·C4**: `review_clip.py`로 거른다 → 입 움직임 높은 것, 얼굴 drift 높은 것을 버림 → 눈 움직임 피크 시각이 비트 시트와 가까운 것 2개를 남김.
   **C2·C3**: `sheet.png`로 눈으로 거른다.
4. 남은 2개를 **직접 재생**해서 설계서의 **합격 기준**을 확인한다.
5. 합격한 것을 `generated/selected/<클립>.mp4`로 복사한다.
6. 실패가 이어지면 프롬프트 B → C(키프레임) 순서로 올린다.
**시도 상한 (비용 보호)**: C1·C4는 **최대 24회**, C2·C3는 **최대 16회**. 넘으면 그 샷은 플랜 B로 간다.
**S6**: 이미지 C를 `selected/S6_C.png`로 복사한다. 영상 생성은 선택이다.
**G3 (통과 기준)**: 선택한 클립이 해당 합격 기준을 모두 충족. **미충족이면 그 샷만 플랜 B**(조립 시 자동으로 대체 컷이 채워진다).

### 4단계 · 조립 (예상 30분 + 수정)
```bash
# 1) 지금 있는 것만으로 조립 (없는 클립은 애니매틱의 대체 컷으로 채워진다)
python3 production/tools/assemble.py --ep E01 --labeled --name E01_cut_v1
# 2) 샷 라벨 없이 최종본
python3 production/tools/assemble.py --ep E01 --name E01_cut_v2
# 옵션: --audio 파일.wav (사운드 교체) / --no-look (질감 필터 없이) / --clips 폴더
```
결과: `production/E01/build/<이름>.mp4`. `--labeled`는 샷마다 `REAL C1.mp4` / `stand-in` / `editor`로 표시해서 **무엇이 실제 클립이고 무엇이 대체 컷인지** 한눈에 보여 준다.
**자동으로 적용되는 것**: 푸시인 · S1 검은 화면+붉은 점 · S1→S2 0.4초 디졸브 · 16.0초 충격 흔들림 · 11.0초와 18.3초 글리치 · CRT 꺼짐 · 테이프 질감(영상 레이어만) · 오버레이 · 사운드
**자동으로 안 되는 것 (직접 보정)**
- **램프 깜빡임 보정**: AI 클립 속 램프가 설계서의 스케줄(1.6초 주기)과 어긋나면 편집 툴에서 마스크로 맞춘다. (설계서 6절)
- 클립 간 노출·색 맞춤
**G4 (통과 기준)**: 설계서 **9절 프레임 단위 QA**의 항목이 모두 맞는다. 특히 `f144`(S3 컷)와 `f288`(S5 컷)이 **안정된 프레임에서 일어나는지**, `f307`에 미아가 램프에 반응하지 않는지.
**편집 툴로 직접 마무리하고 싶다면**: 설계서 6절의 **EDL 표**대로 배치하고, `overlay/E01_overlay_alpha.webm`과 `audio/E01_audio_temp_mix.wav`를 올리면 같은 결과가 나온다.

### 5단계 · 사운드 (예상 1~2시간, 선택이지만 권장)
**현재**: 합성음 임시 믹스(-16 LUFS). **실제 소리가 들어가면 훨씬 좋아진다.**
1. 먼저 임시 믹스로 영상을 끝까지 만들어서 **타이밍을 확정**한다.
2. 아래 소리를 실제로 녹음하거나 라이선스가 명확한 음원에서 구한다: **카세트 슬라이드**(9.2), **도어 닫힘**(10.6), **헤드셋 플라스틱 마찰**(6.5), **손이 닿는 소리**(16.0), **재생·정지 키**(0.0 / 18.3)
3. `stem_sfx.wav`는 끄거나 −6dB 이하로 낮추고 실제 소리를 위에 얹는다. `stem_room`, `stem_tape`, `stem_pad`는 그대로 둔다.
4. 새 믹스를 `-16 LUFS` 근처로 맞춘다. 측정: `ffmpeg -i mix.wav -af ebur128=peak=true -f null - 2>&1 | grep -E "I:|Peak:"`
5. `assemble.py --ep E01 --audio <새 믹스>.wav`로 다시 조립.
**G5 (통과 기준)**: 통합 음량 **-17~-15 LUFS**, 피크 **-1dBFS 이하**, 폰 스피커와 이어폰 양쪽에서 들어 봤을 때 **히스가 거슬리지 않음**.
※ 합성음이 어색하면 말로 알려 주세요. `make_audio.py`의 합성 방식과 `episode.json`의 숫자를 같이 고친다.

### 6단계 · QA와 업로드 (예상 1시간)
1. 설계서 9절 QA와 E01 제작 패키지 9절 QA를 다시 한 번 확인
2. **폰에서 재생** (인스타 미리 보기로 안전 영역 확인)
3. 업로드: 캡션 `Signal OK.` · 해시태그 · 표지 프레임 `overlay/ui_cover_t3.9.png` · 대체 텍스트 (제작 패키지 7절)
4. 프로필 고정 게시물 1번으로 지정
5. **업로드 후**: 단서 장부 C004, C008을 `공개`로 변경
6. **최종 영상 파일을 보관**한다 (E12에서 재업로드할 원본)
7. 웹페이지 `CONFIG.links`에 계정 주소를 넣는다
**G6 (통과)**: 위 항목 완료.

## 5. 도구를 정하는 규칙 (1단계 결과를 반영)
| 상황 | 선택 |
|---|---|
| 한 도구가 4가지 기준을 통과 | 그 도구를 **전 클립**에 사용 |
| C1·C4는 A 도구가 좋고, C2·C3(손·기계 움직임)는 B 도구가 좋음 | **섞어 쓴다.** (스타일이 같은 이미지에서 출발하므로 편집에서 이어진다) |
| 미세한 부분만 움직여야 하는데(헤드셋 컵, 눈) 전체가 같이 움직임 | 움직일 **영역을 지정**할 수 있는 기능(모션 브러시류)이 있는 도구를 C2에 시도 |
| 모든 도구가 화풍을 3D·실사로 바꿈 | 정지 이미지 + 디졸브 기반(플랜 B)으로 가고, 움직임은 편집에서 만든다. 이 경우 **애니매틱이 곧 최종안의 뼈대**다 |
| 비용이 예산을 넘음 | 무료·저가 구간에서 **후보 수를 줄이고 프롬프트 B/C 대신 A를 반복** |
가격은 도구마다 달라서 **결제 전에 공식 가격표를 확인**한다. (조사 때 본 값은 추정치였다)

## 6. 생성 로그 (`generated/LOG.csv`)
한 줄에 한 번의 생성. 열: `id, date, phase, clip, tool, model_version, start_frame, end_frame, prompt_level, seed, duration_s, motion_setting, file, mouth_motion, face_drift_pct, eye_peak_s, lamp_match_pct, lens_gaze, style_fidelity_1to5, cost, verdict, notes`
- `phase`: bakeoff / images / clips
- `prompt_level`: A / B / C
- `verdict`: pick / shortlist / reject, 그리고 이유는 `notes`에
- 검수 수치 열은 `review_clip.py`의 출력값을 옮긴다. **같은 클립의 후보끼리만 비교**한다.
이 로그가 있으면 E02 이후에 "어느 도구·설정이 잘 됐는지"를 그대로 재사용할 수 있다.

## 7. 일정 제안 (대략)
| 날 | 할 일 | 시간 |
|---|---|---|
| 1일차 | 1단계 도구 비교 + 2단계 입력 이미지 | 3~5시간 |
| 2일차 | 3단계: C3, C1 | 3~4시간 |
| 3일차 | 3단계: C4, C2, S6 | 3~4시간 |
| 4일차 | 4단계 조립 + 5단계 사운드 + 6단계 QA·업로드 | 3~4시간 |
시간은 처음 해 보는 사람 기준의 **대략적인 예상**이다. 도구 대기 시간, 실패 횟수에 따라 크게 달라진다.

## 8. 위험과 대응
| 위험 | 대응 |
|---|---|
| 화풍이 3D·실사로 변함 | 1단계에서 조기에 발견. 도구 변경 또는 플랜 B |
| 눈 연기(C1, C4) 실패율 높음 | 키프레임(A-L, A-W) 활용 → 시도 상한 → 정지 이미지 + 디졸브로 대체 |
| 램프 깜빡임이 스케줄과 어긋남 | 편집에서 마스크 보정 (설계서 6절) |
| 손(S6, C2)이 깨짐 | 손 없는 컷 / 정지 이미지 |
| 비용 초과 | 시도 상한, 무료 구간 우선 |
| 도구 정책·가격·버전이 바뀜 | LOG에 **모델 버전**을 기록, 결제 전 공식 페이지 확인 |
| 합성음이 어색함 | 5단계 실제 폴리 보강 / 숫자 조정 |
| 일정이 늘어짐 | **애니매틱을 최소안으로 먼저 업로드 가능**하다는 점을 기억 (전부 실패해도 영상은 나온다) |

## 9. E02 이후에 이 워크플로우를 재사용하려면
도구는 이미 **편 번호를 받는 구조**다. 새 편은 **`production/<편>/episode.json` 하나**를 만들면 오버레이·사운드·조립·검수가 같은 명령으로 돌아간다.
1. `production/E01/`의 구조를 `production/E02/`로 복사하고 `source/`에 새 기준 이미지를 둔다. (`generated/`의 후보와 `build/`는 복사하지 않는다)
2. `E02/episode.json`을 편집한다: `id`, `tape_id`, `side`, `duration`, `overlay.captions`, `audio.timing·events·marks`, `video.shots·effects·lamp`, `review.boxes`
3. 같은 명령에 `--ep E02`를 붙여 실행한다: `make_overlay.py`, `make_audio.py`, `plot_audio.py`, `make_animatic.py`, `assemble.py`, `review_clip.py`
4. 초단위 설계서의 구조(프레임표 → 비트 시트 → 3단계 프롬프트 → 합격 기준 → EDL)를 편마다 작성한다.
5. 시즌 1 기획서의 **편별 비트**에서 행동 사전의 행동 ID를 골라 새 비트 시트를 만든다.
※ 새 효과음이 필요하면 `make_audio.py`의 `build_hits()`에 합성 함수를 추가하고, 새 연출 효과가 필요하면 `assemble.py`의 `Episode.frame()`에 효과 종류를 추가한다.
